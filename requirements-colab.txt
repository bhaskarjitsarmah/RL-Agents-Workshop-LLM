# COLAB / KAGGLE GPU TRAINING STACK.
#
# Read this before changing a line.
#
# STRATEGY: layer on top of the host's PyTorch. DO NOT PIN torch.
#
# The previous version of this file pinned the whole Dec-2024 stack exactly
# (torch==2.5.1, transformers==4.46.3, unsloth==2024.12.4, ...). That looked
# reproducible and was not: on current Colab those pins do not resolve, the
# install aborted, and -- because the setup cell ignored the exit code -- the
# notebooks silently ran on Colab's stock packages instead. Participants then
# hit "bitsandbytes>=0.46.1 required", "No module named 'trl'", and
# "_amp_foreach_non_finite_check_and_unscale_ not implemented for BFloat16",
# none of which name the actual cause.
#
# Pinning torch is also the expensive kind of wrong: it downgrades the host's
# CUDA-matched build, forces a runtime restart mid-workshop, and breaks the
# preinstalled packages compiled against the stock version.
#
# So: floors, not equalities, and torch comes from the host untouched. What the
# code actually needs from these libraries is asserted at runtime instead --
# `_filter_kwargs` in llm_utils/trainers.py drops config kwargs the installed
# TRL does not define and prints what it dropped, and `_dtype_kwarg` handles the
# transformers v4 -> v5 `torch_dtype` -> `dtype` rename. Version drift is
# absorbed there, where it can be seen, rather than frozen here where it rots.
#
# BEFORE THE WORKSHOP, on a fresh Colab T4:
#   python scripts/check_api_surface.py
# It prints the real dataclass fields of SFTConfig/GRPOConfig for whatever
# resolved today. Correct trainers.py against THAT, not against documentation.
#
# Target hardware: free T4 -- Turing (sm_75), 16GB.
#   * no FlashAttention-2  -> attn_implementation="sdpa"
#   * vLLM is unreliable   -> use_vllm=False / fast_inference=False by default
#   * fp16 vs bf16 is decided ONCE, in llm_utils/config.py:torch_dtype(), and
#     every training config keys off the same flag. Never hardcode it again.

-r requirements.txt

# --- Training stack. NOT preinstalled on Colab; floors only. ---

# torch. Older builds fail with "bitsandbytes>=... required" at model load.

# --- torch is deliberately absent. ---
# Colab and Kaggle ship a CUDA-matched build; installing our own replaces it,
# forces a restart, and breaks torchvision ("operator torchvision::nms does not
# exist"). If you are on a bare machine, install torch yourself first:
#   https://pytorch.org/get-started/locally/

# --- Unsloth (~2x faster 4-bit LoRA on a T4) is installed by the SETUP CELL, ---
#     not from here, and UNPINNED.
# It supports CUDA capability >= 7.0, so a T4 (7.5) trains fine, and it is what
# makes NB3 fit in a lunch break. It is kept out of this file for one reason:
# it is the heaviest install in the stack, and a resolve failure here would
# abort the CORE install along with it. The setup cell installs it separately
# and best-effort, so a bad day for unsloth costs speed, not the workshop --
# trainers.py falls back to transformers + bitsandbytes and trains the same
# adapter. Skip the attempt with USE_UNSLOTH=0.
#
# NOTE: unsloth is the one dependency that may still pull its own torch. The
# setup cell checks for that afterwards and tells you to restart the runtime.

# --- Serving (NB7). vLLM on Turing is best-effort: NB7 tries it, measures it if
#     it loads, and falls back to FastAPI+transformers, then llama.cpp on CPU. ---

# --- OpenPipe ART (NB5) is installed by the SETUP CELL, not from here. ---
# Same reasoning as unsloth: it pulls heavy deps that can fail to resolve against
# the host torch, and when it lived in this file a single failure aborted the
# WHOLE install. The setup cell installs it separately and best-effort, so its
# failure cannot break the core; NB5 replays a pre-baked run if it is absent, by
# design. Nothing to do by hand.
#
# THE RULE, for anything added later: if a dependency is optional to the day,
